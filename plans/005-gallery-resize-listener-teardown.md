## Why this matters

`wireLastRowCorrection()` adds a `resize` listener to the window and never removes it. In standard server-rendered WordPress this is harmless — one listener per gallery per page load, released when the page unloads. It only becomes a leak under repeated re-hydration or SPA-style DOM churn, which the Interactivity API does not currently do for these server-rendered blocks. So this is **defensive tidiness**, not a live-bug fix: making the listener (and its debounce timer) an abortable unit owned per wrapper so that, if a teardown path is ever introduced, the leak is already bounded and closeable in one call. The reviewer may legitimately decide the current code is fine as-is for server-rendered use and reject this plan; that is an acceptable outcome (record it in the index).

```ts
// :380-399
function wireLastRowCorrection( layout: HTMLElement ): void {
	correctLastRow( layout );

	// Re-run after the window settles at a new size; every resize event within
	// the debounce window pushes the work further out.
	let timer: ReturnType< typeof setTimeout > | null = null;
	layout.ownerDocument.defaultView?.addEventListener(
		'resize',
		() => {
			if ( timer !== null ) {
				clearTimeout( timer );
			}
			timer = setTimeout( () => {
				timer = null;
				correctLastRow( layout );
			}, RESIZE_DEBOUNCE );
		},
		{ passive: true }
	);
}
```

Called once per wrapper from `init()` (`:438-440`), which already guards double-init via `mountedGalleries.has( ref )` (`:428`). The Interactivity API `init` callback exposes **no unmount hook**, which is why no teardown is wired today.

## Steps

### Step 1: Make the listener + timer an abortable unit owned per wrapper

Change `wireLastRowCorrection` so the `resize` listener is registered with an `AbortSignal`, and the debounce timer is cleared on abort. Track one `AbortController` per wrapper in a module-scope `WeakMap` keyed by the wrapper element, so a future unmount can abort it.

Target shape (adapt names to the file's style):

1. Add beside `mountedGalleries` (`:105`):
   ```ts
   // Per-wrapper teardown for the justified resize listener; abort releases the
   // window listener and the pending debounce. No Interactivity unmount hook
   // exists yet, so this stays latent — it bounds the listener's lifetime and
   // makes a future teardown a single abort() call.
   const galleryTeardowns = new WeakMap< Element, AbortController >();
   ```
2. Change `wireLastRowCorrection` to take the owning wrapper (`ref`) so it can register the controller, OR register the controller in `init()` and pass its `signal` down. Simplest: give `wireLastRowCorrection( layout, signal )` a second `AbortSignal` parameter, pass `signal` to `addEventListener`, and clear the pending timer when the signal aborts:
   ```ts
   function wireLastRowCorrection( layout: HTMLElement, signal: AbortSignal ): void {
   	correctLastRow( layout );

   	let timer: ReturnType< typeof setTimeout > | null = null;
   	signal.addEventListener( 'abort', () => {
   		if ( timer !== null ) {
   			clearTimeout( timer );
   		}
   	} );
   	layout.ownerDocument.defaultView?.addEventListener(
   		'resize',
   		() => {
   			if ( timer !== null ) {
   				clearTimeout( timer );
   			}
   			timer = setTimeout( () => {
   				timer = null;
   				correctLastRow( layout );
   			}, RESIZE_DEBOUNCE );
   		},
   		{ passive: true, signal }
   	);
   }
   ```
3. In `init()` (`:438-440`), create/store the controller and pass its signal:
   ```ts
   if ( justified ) {
   	const controller = new AbortController();
   	galleryTeardowns.set( ref, controller );
   	wireLastRowCorrection( justified, controller.signal );
   }
   ```

Keep the TSDoc on `wireLastRowCorrection` accurate (note the `signal` parameter and the latent-teardown rationale). Update its `@since` to the current cycle's version (see plan 004; default `0.15.0`).

**Verify**: `npm run build` → compiles, no type errors. `npm run lint:js` → exit 0.
