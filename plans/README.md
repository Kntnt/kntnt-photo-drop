Generated by the improve skill on 2026-06-19 (deep code-quality audit, planned against commit `2cf63ed`). Focus of the audit: code quality, comment quality, coding-standard adherence, and test coverage / untested edge cases — *not* UI/UX/functionality, which the maintainer is satisfied with.

**Headline finding: the codebase is in excellent shape.** All quality gates are green (PHPStan level max, PHPCS WordPress standard, Pest, Jest — every one exit 0). The plans below are **incremental hardening, not structural repair**. Each is low-risk and independently shippable.

> **Plans 007–008 are from a separate maintainer feature request (2026-06-19), not the code-quality audit that produced 001–006.** That audit deliberately excluded UI/UX/functionality "which the maintainer is satisfied with"; these two plans implement three behaviour changes the maintainer *then* requested for the gallery's **add-to-media** overlay (the "copy this image into the Media Library" icon, ADR-0015):
> 1. **Single click should add** (007 is unrelated to this; the click change is 008) — today a two-click confirm gate arms then fires; the maintainer wants one click.
> 2. **No `-scaled` downscaling on insert** — **plan 007**.
> 3. **Detect an existing copy and offer a replace-in-place overwrite** instead of silently duplicating — **plan 008** (which also makes the add single-click, since single-click is only safe once dedup catches re-adds).
>
> **Plan 009 is a separate maintainer bug report (2026-06-19):** in Firefox the download-overlay icon both downloads the image *and* opens it in a new tab. Root cause confirmed from a maintainer HAR — the `fetch` succeeds and the blob path runs, but Firefox opens a `blob:` URL whose MIME type it can render (WebP) in a tab even with `download` set. Fix re-types the blob to `application/octet-stream` in `saveFile` (one function, covers both grid and lightbox). Contradicts no ADR — it fulfils `save-file.ts`'s existing no-new-tab contract. Independent of 001–008.
>
> Both 007 and 008 are **P1** (requested functionality), unlike the P2/P3 hardening above. **008 amends ADR-0015** — it overturns the two-click add gate and the "no dedup; each confirmed click adds another copy" decision. This is sanctioned because the maintainer is authorising it; the amendment is a required step in 008, not a silent deviation. **007 adds a one-line clarifying note to ADR-0015** (full-resolution insertion is consistent with the existing "WordPress generates its own sub-sizes" wording).

## Findings considered and rejected

So nobody re-audits these — each was opened against the cited code and dismissed:

- **`Admin/Admin_Page.php` (2366 lines) "god object" → extract a presenter.** Real size, but it is a cohesive, thoroughly-commented CRUD admin page; a ~500-LOC presenter extraction is high-churn risk for low real benefit while the maintainer is satisfied with the admin UX. Revisit only if the file starts attracting bugs.
- **`Imaging/Gd_Webp_Codec.php:182` `round()`→`max(1,…)` "aspect distortion".** Correct handling of a degenerate input (a panorama whose true scaled height would be sub-pixel). Switching to `ceil()` would make *every* thumbnail a pixel taller — strictly worse. Not a bug.
- **`gallery/slideshow-resync.ts:96` "DOMParser throws on malformed HTML".** False: `DOMParser.parseFromString(html, 'text/html')` uses the lenient HTML parser, which never throws (unlike `application/xml`). No guard needed.
- **AGENTS.md capability-filter list is stale / `editor_notice_capability` missing.** False positive from a grep that could not see filter names passed as variables/arguments. All documented filters exist (`editor_notice_capability` at `Rendering/Render_Gallery.php:1075`; the six `default_*` filters via `Storage/Rendition_Defaults.php`).
- **`private constructor` → `#` in `gallery/lightbox.ts` / `slideshow.ts`.** A constructor cannot be `#`-private in TypeScript; a `private constructor` is the standard factory idiom. The standard's `#camelCase` rule governs fields, which the code already uses.
- **`Plugin::log()` re-reads its level constant per call — "performance".** Micro-optimization; `error_log()` dominates the cost by orders of magnitude, and the guard short-circuits before it. Not worth the added state.
- **`gallery/focus-trap.ts` redundant `=== undefined` checks.** Required by `noUncheckedIndexedAccess`; the suggested "tighten the length guard" rewrite trades a clear invariant for a subtle one. Leave it.
- **"Systematic missing paragraph comments / PHPDoc."** Overstated by the audit subagents. Spot-checks across `Atomic_Writer`, `Gd_Webp_Codec::scale`, and the REST controllers show the paragraph-comment and PHPDoc discipline is present, correct, and consistent.
- **F3 edge cases claimed missing but already tested:** single-element `justified-rows` (`justified-rows.test.ts:32`), multi-dot `file-filter` (`file-filter.test.ts:74`), and the full `lightbox-index` removal/wrap/empty matrix (23 cases). Only the `addToMedia` malformed-`id` branch (plan 003) is a genuine gap.
- **`Atomic_Writer` short-write (partial disk-full) test.** The `file_put_contents() === false` consequence is already covered (`AtomicWriterTest.php:59,73`); the distinct short-positive-count branch produces the identical discard-and-return-false outcome and cannot be exercised without mocking the internal `file_put_contents`, which Brain Monkey does not do in this harness (the suite only ever stubs WordPress functions). Not worth a new mocking dependency for an already-covered effect. (This is why plan 002 narrowed from "durability/ingestion failure branches" to just the Ingestor mkdir path.)
- **`Thumbnailer` / codec corrupt-main decode test.** Already covered: `ThumbnailerTest.php:346` (`'renditions_present is false when the main cannot be decoded'`), `:225` (unreadable main yields no derived files), and `:334` (encode-to-null failure via `Encode_Failing_Codec`). No gap.
